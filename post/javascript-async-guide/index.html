Promise 与 async/await：从状态机理解异步控制流

不把 await 记成“等待结果”，而是理解它如何暂停当前 async 函数、让出调用栈，并在微任务中恢复后续执行。

2026-07-1011 分钟JavaScript · Promise · 并发

一、Promise 是一个只能单向迁移的状态机

Promise 初始为 pending，之后只能迁移到 fulfilled 或 rejected，而且一旦完成就不能再次改变。

pending -> fulfilled(value)
pending -> rejected(reason)

resolve 并不总是立即变成 fulfilled。如果传入另一个 Promise，它会采用对方的最终状态。

二、构造函数同步执行，回调异步执行

console.log('A');

const promise = new Promise(resolve => {
  console.log('B');
  resolve('result');
});

promise.then(value => console.log('D', value));
console.log('C');

// A B C D result

Promise 构造器里的函数在当前调用栈同步执行；then 注册的回调进入微任务队列，等当前栈清空后运行。

三、then 返回新的 Promise

链式调用成立，不是因为同一个 Promise 被不断修改，而是每个 then 都返回一个新 Promise：

fetchUser()
  .then(user => fetchOrders(user.id))
  .then(orders => summarize(orders))
  .catch(error => report(error));

回调返回普通值，新 Promise 会 fulfilled；抛出异常或返回 rejected Promise，新 Promise 会 rejected；返回另一个 Promise，则等待它完成。

四、async/await 是链式控制流的语法

async function loadSummary() {
  const user = await fetchUser();
  const orders = await fetchOrders(user.id);
  return summarize(orders);
}

async 函数总是返回 Promise。执行到 await 时，表达式先被转成 Promise；函数暂停，控制权回到调用方；Promise 完成后，函数剩余部分作为微任务继续执行。

await 暂停的是当前 async 函数，不会阻塞 JavaScript 线程，也不会阻止其他任务继续运行。

五、串行和并发不能写混

错误的无依赖串行

const profile = await fetchProfile();
const messages = await fetchMessages();
const settings = await fetchSettings();

三个请求互不依赖，却被逐个等待，总耗时接近三者之和。

正确的并发启动

const [profile, messages, settings] = await Promise.all([
  fetchProfile(),
  fetchMessages(),
  fetchSettings()
]);

Promise.all 适合“全部成功才有意义”的任务；需要收集每个结果时使用 Promise.allSettled；只关心最快成功时使用 Promise.any。

六、异常传播的真实边界

async function run() {
  try {
    return await riskyTask();
  } catch (error) {
    throw new Error('任务执行失败', { cause: error });
  }
}

try/catch 只能捕获被 await 的 rejection 和同步异常。启动一个 Promise 却不 await，也不 return，它的失败不会被当前 catch 接住。

try {
  riskyTask(); // 未 await，当前 catch 捕获不到后续 rejection
} catch (error) {
  // 不会执行
}

七、并发数量也需要控制

对一万个任务直接 Promise.all 可能瞬间打满连接池或下游接口。可以使用固定并发 worker：

async function mapLimit(items, limit, worker) {
  const results = new Array(items.length);
  let cursor = 0;

  async function runWorker() {
    while (cursor < items.length) {
      const index = cursor++;
      results[index] = await worker(items[index]);
    }
  }

  await Promise.all(Array.from({ length: limit }, runWorker));
  return results;
}

八、常见误区清单

  • 在 forEach 中使用 async，却期待外层等待完成。
  • 忘记 return Promise，导致链式流程提前结束。
  • 把所有任务都 Promise.all，忽略并发上限。
  • catch 后吞掉异常，让上层误判成功。
  • 把 await 当作线程阻塞，错误分析执行顺序。

九、快速判断方法

阅读异步代码时，只需要持续问三件事：这个函数返回哪个 Promise？当前 await 暂停的是哪一层函数？多个任务是先全部启动还是逐个启动？大多数异步顺序问题都能由此还原。
